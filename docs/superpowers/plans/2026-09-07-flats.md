# Flats Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Households with rooms: named flats with one daily rhythm, rooms lit in order, room-aware life events, a Houses tab, a Home strip.

**Architecture:** `FlatConfig` in the scene model with JSON and presets; `evaluateFlats()` in the engine fills lit and TV bitmaps per simulated minute and feeds the existing event layer with room rates; status and presets extended; mock mirrors; Houses view, Home strip, Scene "taken" discs.

**Tech Stack:** arduino-pico core 5.5.1, ArduinoJson 7, vanilla JS, Python 3, GNU make.

**Spec:** `docs/superpowers/specs/2026-09-07-flats-design.md`. Every number is there; read it first.

## Global Constraints

- No em dashes anywhere. Header comments end with `Invector Embedded Systems AB`.
- Web API handlers stay server-agnostic. Nothing external fetched by the UI.
- `make` warning-free; flash only through `make upload`.
- Every `SceneConfig`/`GroupConfig`/`FlatConfig` object static or a member (8 kB stack).
- Existing JSON names and enum numbering unchanged; flats are additive; a scene without `flats` loads as before.
- Whole page under 40 kB gzipped.
- The controller commits at the end.
